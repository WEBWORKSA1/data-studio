# Data.Studio: Phase-wise Build Prompts

Copy each phase into an AI coding assistant in order. Each phase assumes the previous one is complete. The current repository implements Phases 0–7. Phase 8 is the post-launch growth roadmap.

**Global constraints (prepend to every phase):**
> Static site for GitHub Pages (free plan, `main` branch root), HTML + CSS + vanilla JS only, no build step, relative links everywhere (site must work at `/data-studio/` and at the custom domain root). AdSense publisher `ca-pub-6620975821265271`: put `<script async src="https://pagead2.googlesyndication.com/pagead/js/adsbygoogle.js?client=ca-pub-6620975821265271" crossorigin="anonymous"></script>` and `<meta name="google-adsense-account" content="ca-pub-6620975821265271">` in the `<head>` of every indexable page. The top of every page shows "Contact, if you are interested in this website / domain name / Sponsorship / Advertisement / Partnership", linked to https://web.works/contact without displaying the URL. All forms deliver to the owner's single inbox via FormSubmit AJAX. The address is assembled at runtime from character codes (or a FormSubmit alias in config) and must never appear as text or in a `mailto:` anywhere. Always write the brand as "Data.Studio". Never create content about, or imply affiliation with, Google's "Data Studio" / Looker products.

## Phase 0: Positioning & guardrails
> Define Data.Studio as "the free studio for working with data": private in-browser tools, open data, live data, guides and a done-for-you analytics desk. Write the sitemap (Home, Tools hub + 7 tools, Chart Guide, Datasets, Live Data, Learn, Guides hub + 8 guides, Glossary, Services, Contests, Careers, Support, Advertise, About, Contact, Privacy, Terms, Disclaimer, 404). Write a trademark policy: generic descriptive use only, non-affiliation notice in footer + disclaimer page + FAQ, no Google trade dress, no content targeting Google's product.

## Phase 1: Design system & shell
> Create `assets/css/site.css`: tokens (ink #0A0F1F, brand #5B5BF7, teal #12C29B, amber #FFB020, rose #F2557A), Inter + JetBrains Mono, buttons, cards, badges, chips, grid utilities, hero with a subtle data-grid background, CTA band, forms (including multi-step), tables, KPI tiles, FAQ accordions, YouTube lite-embed, cookie banner and sticky CTA. Make it fully responsive (breakpoints 1060/920/640). Create `assets/js/site.js`, which injects the header (sticky nav + mobile toggle + "Hire Data Experts" CTA) and a 5-column footer (newsletter form, tools, explore, work with us, company, trademark line) relative to `<body data-root>`. It also handles form submission with honeypot, success and error states, multi-step forms with progress bar and per-step validation, query-string prefill, cookie notice (essential-only sets non-personalised ads), YouTube click-to-load embeds, the sticky CTA after scroll, and the JSON data helpers. Create `assets/js/config.js` for form alias, donation links and contest prizes/themes.

## Phase 2: In-browser tools
> Build 7 tools with PapaParse and Chart.js from jsDelivr plus a shared `assets/js/tools.js` (parse, dropzone, download, copy, table render, stats, normal CDF and inverse, palettes): (1) Chart Maker: bar / horizontal / stacked / line / area / pie / doughnut / scatter / radar, column pickers, sort, palettes, white-background PNG export, `?type=` param. (2) CSV ⇄ JSON: auto delimiter, typing, three JSON shapes, nested flattening. (3) Data Profiler: type inference, missing, distinct, duplicates, IQR outliers, histograms, top values, issue list, profile export. (4) Pivot Table: rows / cols / values, six aggregations, totals computed from raw rows, CSV export. (5) Data Cleaner: trim, collapse spaces, null standardisation, blank and duplicate removal, case, snake_case headers, find/replace with regex, change log. (6) A/B Test Calculator: two-proportion z-test, one- or two-sided, CI, uplift, SRM check. (7) Sample Size: A/B (relative/absolute MDE, α, power, variants, Bonferroni, duration) and survey (MoE, confidence, finite population, response rate). Each tool page gets 200–400 words of original how-to content and a contextual sticky CTA to the Services brief.

## Phase 3: Content engine
> Write 8 original guides (800–1,200 words each) with Article schema, a sidebar tool CTA and a services CTA: choosing charts, data cleaning checklist, A/B testing, KPI dashboard design, descriptive statistics, pivot tables, CSV vs JSON vs Parquet, finding and evaluating open data. Build an interactive Chart Guide (24 chart types, filter by 8 goals, use/avoid, deep-link to Chart Maker), a 60+ term glossary (A–Z jump, live filter), and a 40+ source open-datasets directory from `data/datasets.json` (category chips, search, licence notes, "suggest a source" form).

## Phase 4: Live data automation
> Write `scripts/update-data.mjs` (Node 20, zero deps, per-feed try/catch, keep last good data on failure). It fetches ECB FX via Frankfurter (latest + 30-day EUR series + day change), World Bank WDI (GDP, population, GDP per capita, life expectancy, internet users; `mrnev=1`) for 20 economies, arXiv newest papers, Hacker News data stories (Algolia, 14 days, points>15), GitHub rising data repos, and YouTube RSS from data educators (keyword filter for general channels). It writes `data/*.json` and `data/meta.json` and bumps sitemap `lastmod` for dynamic pages. Add a GitHub Actions workflow (cron every 6 h + manual + on push) with `contents: write` that commits changes. Build `live.html` and `learn.html` to render these, with graceful "refreshing" states and last-updated stamps.
