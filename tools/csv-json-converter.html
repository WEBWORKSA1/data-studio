How the converter works

CSV → JSON reads the first row as field names and turns each following row into an object. Turn on type conversion and values like 42, 3.14 and true become real numbers and booleans instead of strings. Pick Array of arrays for compact output, or Keyed by first column to build a lookup object (useful when the first column is a unique ID).

JSON → CSV accepts an array of objects, a single object, or an object holding an array. Nested objects are flattened using dot notation: {"user":{"name":"Ana"}} becomes a user.name column. Arrays inside a record are kept as JSON text in a single cell, so nothing is lost. Columns are the union of all keys, so records with missing fields still line up.

Common gotchas

  • Leading zeros (ZIP codes, phone numbers) get stripped when converted to numbers. Turn off type conversion to keep them as text.
  • European CSVs often use semicolons, because the comma is the decimal separator. Auto-detect handles this, or choose the delimiter manually.
  • Quotes and line breaks inside fields are handled per RFC 4180 by the PapaParse library.
